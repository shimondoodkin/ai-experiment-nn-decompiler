# ast3 and Tanh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build tool version `ast3`, which is `ast2` plus the four review fixes and a tanh→sigmoid rewrite. Develop it on
sigmoid seeds 0–5 and tanh development nets, freeze it, run it once on fresh held-out nets (sigmoid seeds 6–8, tanh
formula seed 2 and Iris seeds 3–5), then replace `ast2` with `ast3` if `ast3` is never worse.

**Architecture:**
- **Tanh rewrite:** a pure `MLP → MLP` function, `as_sigmoid` in `nndc/model.py`.
- **`refactor`:** gets a version that switches on kink merge and the tanh rewrite. The routes see the rewritten net;
  the checker sees the original.
- **`kinks.py`:** gets the four fixes.
- **Report:** reads the newest version, and `<root>/heldout.json` for the held-out set.

**Tech Stack:** Python 3.13, NumPy, SciPy, pytest, `uv`.

**Spec:** `docs/design/2026-10-29-ast3-tanh-design.md`

## Global Constraints

- **ReLU results unchanged:** `experiments/equivalence.py` must report 0 differences.
- **Plain `nndc ast` is unchanged:** it stays the project B tool, with no kink merge and no tanh rewrite.
- **Older verdicts never change:** `ast3` uses `counterexamples_ast3.json`.
- **Held-out nets are built only after the freeze commit.** Tool development does not read
  `HEURISTICS_heldout.md`.
- **Fixed parameters:** `|cos| > 0.995`; snap levels `(0.05, 0.02, 0.01, 0.005, 0.0)`; position window
  `tol · Σ|n_i|·span_i`; constant window `tol · R`, where `R` is the range of the net's output on the fit samples.
  All the kink-merge parameters stay.
- **"Worse"** (`ast3` vs `ast2`, on one run): `ast2` passes and `ast3` does not; or `ast2` recovers the formula and
  `ast3` does not; or both pass and `ast3` has more nodes.
- **Commits:** code commits and `data:` commits are separate, with no attribution lines.

## Review Focus

1. **A tanh net with mixed layers** (`["relu", "tanh"]`): only the tanh layers are rewritten, and the output is
   unchanged. Test: `test_as_sigmoid_mixed_layers`.
2. **Antiparallel kinks on one line** must merge, with strengths added in one orientation. Test:
   `test_merge_antiparallel`.
3. **A line with a small range over the box** (normal mostly along a short input): the position window must be
   that line's own range. Test: `test_position_window_follows_line`.
4. **The `tol = 0` level folds out-of-box lines** and refits. Test: `test_tol0_folds`.
5. **`--name ast2` is refused** (its code is gone), and plain `ast` on a tanh net does not rewrite it. Test:
   `test_versions`.

### Task 1: Tanh rewrite

**Files:** `nndc/model.py`; test `tests/test_model.py`

**Interfaces:**
- Produces `as_sigmoid(mlp: MLP) -> MLP`. For each tanh layer `i`:
  - `W_i' = 2 W_i`, `b_i' = 2 b_i`, act `sigmoid`;
  - the next layer becomes `W_{i+1}' = 2 W_{i+1}` and `b_{i+1}' = b_{i+1} − W_{i+1} @ 1`.

  Other layers are copied. The function is stdlib + NumPy only (`model.py` goes into blind folders).

- [ ] **Step 1: tests.**
  - `test_as_sigmoid_matches_tanh`: random nets `[2,4,1]` tanh and `[3,5,4,1]` tanh+tanh. Assert
    `|forward(as_sigmoid(m)) − forward(m)| ≤ 1e-5` on 2000 points, and that every act is `sigmoid`.
  - `test_as_sigmoid_mixed_layers`: `["relu","tanh"]` gives acts `["relu","sigmoid"]`, outputs equal within
    1e-5, and the relu layer's weights are unchanged.
  - A net with no tanh is returned as an equal copy.
- [ ] **Step 2:** run them and see them fail (ImportError). **Step 3:** implement. **Step 4:** `uv run pytest
  tests/test_model.py -q` passes. **Step 5:** commit `feat: tanh layers rewritten exactly as sigmoid layers`.

### Task 2: The four kink-merge fixes

**Files:** `nndc/heuristics/kinks.py`; test `tests/test_kinks.py`

**Interfaces:**
- `merge_lines(kinks, off, cos_min)` merges when `|n_a·n_b| > cos_min`. A kink antiparallel to the group is used
  as `(−n, −d, strength)`; its `+y` part is dropped, because `refine` refits the affine part.
- `SNAP_LEVELS = (*SNAP_TOLS, 0.0)`. The route uses `snap_fit` at every level, and no separate unsnapped candidate.
- `snap_fit`:
  - the position window is `tol · Σ_i |n_i|·span_i`, with `n` the real-coordinate normal (largest |component| =
    1);
  - after the coefficients, the constant is `nicest_in(c − tol·R, c + tol·R)` when `tol > 0`, where
    `R = y.max() − y.min()`.
- `kink_merge` trace `winner.tol` can be `0.0`.

- [ ] **Step 1: tests.**
  - `test_merge_antiparallel`: `Kink([1,0], −0.5, 2.0)` and `Kink([−1,0], 0.5, 1.0)` merge into one line with
    strength 3.0.
  - `test_position_window_follows_line`:
    - spec `x0 ∈ [0, 200]`, `x1 ∈ [0, 1]`, one term with normal `{x1: 1, x0: 0.001}` at `t = 0.433`;
    - at tol 0.05 the window is `0.05 · (0.2 + 1) = 0.06`, so `t` snaps into `(0.373, 0.493)`;
    - with the old `max span` it would have snapped to 0.
  - `test_tol0_folds`: the `_tax_like(edge=205)` fit at `tol = 0` drops the out-of-box term and keeps the other
    values unrounded.
  - `test_constant_rounded`: `_tax_like` with `y + 0.0137` at tol 0.05 gives a constant on a nice grid (`nicest_in`
    result) with `|c − 0.0137| ≤ 0.05·R`.
- [ ] **Step 2:** run them and see them fail. **Step 3:** implement. **Step 4:** `uv run pytest tests/test_kinks.py
  -q` passes. **Step 5:** commit `feat: kink merge v2 — antiparallel merge, tol-0 fold, line-range position
  window, rounded constant`.
