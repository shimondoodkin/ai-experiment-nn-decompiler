# Repair loops edit weights, never decompiled code

Every stage of the proposed cycle has strong prior work. The stages are: take a block out of a trained network, decompile it to code, fix its algorithm using the inputs where the network is wrong, and put it back as weights or as CPU code. The searches behind this report found **no published work that joins all four stages**. Network repair (PRDNN, APRNN, REASSURE, Arachne, CARE) and transformer model editing (ROME, MEMIT, GRACE) fix networks from failing inputs, but they work on weights. A human or LLM never reads or edits a program. Program-to-network compilers (KBANN, Tracr, ALTA) and hybrids that keep a module as code (Compiled Neural Networks, Mixture of Lookup Experts) cover reinsertion. The three closest full cycles each miss one stage. KBANN (1990–94) inserts rules, trains, and re-extracts, but backprop does the fixing. PROPEL (NeurIPS 2019) alternates between a program and a neural residual, but it fits the program by imitation rather than by fixing failures. GAM Changer (KDD 2022) and the GPT-4 GAM-repair work let humans or an LLM fix model logic, but on glass-box additive models that need no decompilation or reinsertion. The combination is therefore claimable as "not found in prior work we searched", provided the claim names the combination and not the parts. One distinction matters most for the repo. The existing check-and-repair loop chases *fidelity to the net*, while the fix cycle deliberately *breaks* fidelity to chase the true task. The repair literature's three standard numbers measure exactly that trade: **efficacy** on the failing set, **generalization** to held-out failures, and **drawdown** on inputs the net already got right. Step 4 should report those three numbers on nets with planted, known bugs before trusting anything measured on Iris, where 150 flowers make one flower worth 0.67 percentage points.

## Weight-space repair already fixes nets from failing inputs, and measures the cost

The formal-methods line edits weights so that a specification holds on given failing points, and it proves the result. **PRDNN** (Sotoudeh and Thakur, PLDI 2021) converts any network to a "Decoupled DNN". In that form, repairing one layer becomes a linear program, and repair over a whole polytope reduces to point repair on the vertices of its linear regions. If the LP is feasible, the result is a minimal single-layer repair. If it is infeasible, no single-layer repair of that layer exists ([arXiv 2104.04413](https://arxiv.org/pdf/2104.04413)). **APRNN** (PLDI 2023) gives the same kind of guarantee without changing the architecture, for fully-connected, convolutional, pooling and residual layers ([Thakur PLDI 2023](https://thakur.cs.ucdavis.edu/bibliography/PLDI2023.html)). **REASSURE** (Fu and Li, ICLR 2022) leaves the existing weights alone. It adds a patch network gated to the linear region of each buggy input, and it is sound, complete, minimal, polynomial-time and **local**: outputs outside the repaired regions do not change ([arXiv 2110.07682](https://arxiv.org/pdf/2110.07682)). That patch amounts to the program `if input in region R: add correction`, the weight-space twin of an `if` branch an agent would insert into decompiled code. **NNrepair** (Usman et al., 2021) is the one precedent that treats the network as a program. It translates a Keras model to Java, runs symbolic execution on it, and lets a solver change the weights into suspicious neurons. Accuracy rose by 45.56 points on poisoned data and 10.40 points on adversarial data ([arXiv 2103.12535](https://arxiv.org/pdf/2103.12535); [review](https://velog.io/@thdalwh3867/%EB%85%BC%EB%AC%B8%EB%A6%AC%EB%B7%B0-NNrepair-Constraint-based-Repair-of-Neural-Network-Classifiers)). Even there, a solver repairs weights rather than anyone editing the code's logic.

PRDNN's experiments are the best published evidence on what a repair costs, and they set up the comparison step 4 needs. On ImageNet SqueezeNet with natural adversarial examples, both provable repair and plain fine-tuning fixed 100% of the repair set. Provable repair lost **1.1–5.3%** on originally-correct inputs, while fine-tuning lost **8.2–15.4%**. A conservative, early-stopped fine-tune lost almost nothing but fixed at most 28% of the failures. On the ACAS Xu collision-avoidance net, provable repair had **zero drawdown on all 5,466 points and 94.69% generalization** in 21 seconds. Fine-tuning broke 650 previously-correct points and timed out. The result is not one-sided. On an MNIST ReLU net, one fine-tuning configuration reached 60% generalization at 3.2% drawdown, beating provable repair's 42.9–46.0% ([ar5iv 2104.04413](https://ar5iv.labs.arxiv.org/html/2104.04413)). Fine-tuning is therefore a mandatory baseline, not a strawman.

The software-engineering line localizes faults from failing inputs and then searches, with no guarantees. **Arachne** (TOSEM 2023) ranks weights by gradient and forward impact on failing inputs, then tunes only those by particle swarm or differential evolution. Its patches fixed **61.3% of unseen misbehaviour against 10.2%** for the prior best technique ([KAIST record](https://dspace.kaist.ac.kr/handle/10203/307190); [arXiv 1912.12463](https://arxiv.org/pdf/1912.12463)). **CARE** (ICSE 2022) picks "guilty" neurons by causal effect. It improved fairness by 61.91% on average and cut backdoor success from over 98% to under 1% while keeping accuracy ([arXiv 2204.09274](https://arxiv.org/pdf/2204.09274)). MODE (FSE 2018) and Apricot (ASE 2019) retrain or move weights toward sub-models that get the failures right. A later tool paper reports no public implementation for either ([MODE](https://people.cs.umass.edu/~shiqingma/papers/FSE18.pdf); [Apricot](https://2019.ase-conferences.org/details/ase-2019-papers/79/Apricot-A-Weight-Adaptation-Approach-to-Fixing-Deep-Learning-Models)). ArchRepair makes a *block* the unit of repair, as the user's idea does, but changes the architecture rather than the algorithm ([arXiv 2111.13330](https://arxiv.org/pdf/2111.13330)).

## Transformer editors treat the MLP sublayer as a memory to rewrite

For step 6, the closest analogue is model editing. It assumes that a transformer's MLP sublayer works as a linear key-value memory and solves for a weight change. **ROME** (NeurIPS 2022) uses causal tracing to find the layer that stores a fact, then applies a closed-form rank-one update to that layer's MLP weights so a key maps to a new value while other keys keep theirs ([arXiv 2202.05262](https://arxiv.org/pdf/2202.05262); [rome.baulab.info](https://rome.baulab.info)). **MEMIT** (ICLR 2023) spreads thousands of such edits across MLP layers 3–8 of GPT-J and also edits GPT-NeoX ([memit.baulab.info](https://memit.baulab.info/)). MEND trains hypernetworks that turn a gradient into a low-rank update. Knowledge Neurons edits single FFN neurons. Both are cited from memory and were not re-checked ([MEND](https://arxiv.org/abs/2110.11309); [KN](https://arxiv.org/abs/2104.08696)). Santurkar et al. apply the same rank-one idea to vision. A human picks a rule such as "snowy road → road", and one layer is rewritten to follow it ([NeurIPS 2021](https://proceedings.neurips.cc/paper/2021/hash/c46489a2d5a9a9ecfc53b17610926ddd-Abstract.html); [MadryLab/EditingClassifiers](https://github.com/MadryLab/EditingClassifiers)). GRACE and SERAC keep the original block and route matching inputs to a stored correction. That is a model-plus-lookup hybrid, structurally the "keep the fix as code beside the block" option with a codebook in place of readable logic. **EasyEdit** runs ROME, MEMIT, MEND, GRACE and WISE under one harness. Its metrics are reliability, generalization, locality and portability ([GitHub zjunlp/EasyEdit](https://github.com/zjunlp/EasyEdit); [arXiv 2308.07269](https://arxiv.org/pdf/2308.07269)).

The critique that matters most for the user's plan is **Hase et al. (NeurIPS 2023)**. They found that the correlation between where causal tracing localizes a fact and how well an edit at that layer works is **near zero** for ROME, MEMIT and fine-tuning. Which layer gets edited predicts success far better than localization does ([NeurIPS 2023](https://papers.neurips.cc/paper_files/paper/2023/hash/3927bbdcf0e8d1fa8aa23c26f358a281-Abstract-Conference.html); [arXiv 2301.04213](https://arxiv.org/pdf/2301.04213)). Decompiling block X and seeing failing inputs flow through it does not show that X is the best block to fix. The closest interpretability-guided precedent is **SHIFT** (Marks et al., ICLR 2025): humans label sparse-autoencoder features as spurious and ablate 55 of them to debias a profession classifier ([ICLR 2025 PDF](https://proceedings.iclr.cc/paper_files/paper/2025/file/3ba4d47a83e498c2b1a0868cba20f6de-Paper-Conference.pdf)). A critique showed that ablating only 10 token-level features reached 85.6% against 88.5%, so the benchmark was easy and equal-affordance baselines nearly match ([Alignment Forum](https://www.alignmentforum.org/posts/QdxwGz9AeDu5du4Rk/shift-relies-on-token-level-features-to-de-bias-bias-in-bios)). A code-level fix that is never compared against fine-tuning and PRDNN on the same failing set is open to the same objection.

## Compiling back is exact only for continuous piecewise-linear code

Reinsertion as weights has a clean theoretical boundary. A function from Rⁿ to R is computable *exactly* by a ReLU network **if and only if it is continuous piecewise linear** (Arora et al., ICLR 2018) ([arXiv 1611.01491](https://arxiv.org/abs/1611.01491v3)). The repo's primitives fall almost entirely on the exact side, through standard identities: max(a,b) = a + relu(b−a), min(a,b) = a − relu(a−b), |x| = relu(x) + relu(−x). Linear tests are linear layers. A fixed program built from relu, min, max, abs and linear maps therefore compiles back to a ReLU MLP with no error. The exception is an `if/else` whose branches disagree at the threshold. That is a jump, and a ReLU net can only approximate it with a steep ramp, relu(z/ε) − relu(z/ε − 1). The ramp is exact outside a margin of width ε and wrong inside it, and it inflates weight norms by 1/ε. Tracr makes the same split: categorical maps compile to exact lookup tables, numerical maps are discretized approximations, and attention uses a temperature of 100, so it is near-hard but not hard ([ar5iv Tracr](https://ar5iv.labs.arxiv.org/html/2301.05062)). The tax-bracket and window programs, once snapped, are exactly the cases where this margin decides whether "compile the fix back" means "reproduce the fix".

The compilers themselves are runnable. **Tracr** compiles RASP programs into decoder-only transformer weights (NeurIPS 2023; [google-deepmind/tracr](https://github.com/google-deepmind/tracr)). **ALTA** adds a symbolic interpreter and a weight compiler (TMLR 2025; [google-deepmind/alta](https://github.com/google-deepmind/alta)). **Learning Transformer Programs** runs the other way, training constrained transformers that convert to debuggable Python ([NeurIPS 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/995f693b73050f90977ed2828202645c-Abstract.html)). For rules and trees, KBANN maps propositional rules into initial weights ([Towell and Shavlik AIJ 1994](https://cs400-web.cs.wisc.edu/nchou/common/site/p/ml/ftp/towell.aij94.pdf)). **DJINN** maps a decision tree to a network's architecture and initial weights, then fine-tunes it. The network starts near the tree's accuracy and ends above it ([arXiv 1707.00784](https://arxiv.org/pdf/1707.00784); [LLNL/DJINN](https://github.com/LLNL/DJINN)). Hummingbird compiles tree ensembles exactly to tensor operations, but the result is a tensor program, not an MLP, and it can run slower than native code on deep trees ([USENIX OSDI 2020](https://www.usenix.org/conference/osdi20/presentation/nakandala); [OctoML](https://octo.ai/blog/compiling-classical-ml-for-performance-gains-up-to-30x-and-hardware-portability)).

Training after reinsertion keeps accuracy but does not reliably keep the algorithm. Tracr's authors compressed a compiled model by gradient descent. One model stayed near-perfect while its representation drifted to about **0.8 cosine similarity**, encoding a variable numerically instead of one-hot ([ar5iv Tracr](https://ar5iv.labs.arxiv.org/html/2301.05062)). Jain et al. found that compiled weights train unstably, with gradient spikes, unless small Gaussian noise is added and SGD replaces adaptive optimizers ([arXiv 2311.12786](https://arxiv.org/pdf/2311.12786)). If the fixed block is reinserted and then fine-tuned, the fix has to be re-decompiled afterwards to show it survived.

Keeping the fix as code instead of weights has fewer precedents, and the existing ones are mostly narrow. **Compiled Neural Networks / Neural Comprehension** (ICLR 2024) splice Tracr-compiled rule modules for copy and add-with-carry into a pretrained language model and route each token to one or the other ([arXiv 2304.01665](https://arxiv.org/abs/2304.01665v3); [WENGSYX/Neural-Comprehension](https://github.com/WENGSYX/Neural-Comprehension)). **Mixture of Lookup Experts** (ICML 2025) turns FFN experts into lookup tables before inference and gets dense-model speed ([PMLR](https://proceedings.mlr.press/v267/jie25b.html); [JieShibo/MoLE](https://github.com/JieShibo/MoLE)). Interpretability replacements show the risk of approximate swaps. Anthropic's cross-layer transcoder replacement matches the original model's next token on only about **50%** of prompts unless per-prompt error terms are added back ([Circuit Tracing methods](https://transformer-circuits.pub/2025/attribution-graphs/methods.html)). Transcoders do better per layer but still approximate ([arXiv 2406.11944](https://www.arxiv.org/abs/2406.11944); [transcoder_circuits](https://github.com/jacobdunefsky/transcoder_circuits)). The repo's decompiled programs are checked equal to the block before any fix, so this fidelity gap should not appear. That is a real advantage, and step 6 should measure it on transformer MLPs rather than assume it. On speed, the precedents for step 5 are conditional execution and logic. UltraFastBERT runs 12 of 4,095 neurons per layer and reports **78×** on the FFN in CPU code while keeping 96% of BERT-base GLUE ([arXiv 2311.10770](https://arxiv.org/abs/2311.10770v2)). Differentiable logic-gate networks classify over a million MNIST images per second on one core ([NeurIPS 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/0d3496dd0cec77a999c98d35003203ca-Abstract.html)). No source measured the cost of a GPU-to-CPU round trip for a code block spliced into a GPU model.

## Three earlier cycles ran extract, fix, reinsert without readable code

**KBANN and NofM** (Towell and Shavlik, 1990–94) ran the full loop in its 1990s form: insert approximately correct rules as weights, refine them with backprop on data, then extract refined M-of-N rules. The extracted rules "closely reproduce the accuracy of the network". They beat rules refined symbolically and remain comprehensible ([MLJ 1993](https://mlanthology.org/mlj/1993/towell1993mlj-extracting)). On the promoter dataset KBANN scored 93.70% ([UW README](https://ftp.cs.wisc.edu/machine-learning/shavlik-group/datasets/promoters-large/README)). Two details matter for the repo. First, backprop did the fixing, and the extracted rules *matched* the net rather than beating it. The repo's finding goes further: in 16 of 29 formula nets the snapped program is *more* correct than the net, with no failing data used at all. Second, RAPTURE (Mahoney and Mooney, 1993) showed early that a useful fixer has to be able to change *structure*, adding rules, and not just tune constants. Fu's certainty-factor revision could not ([RAPTURE PDF](https://www.cs.utexas.edu/~ml/papers/rapture-connsci-94.pdf)). No maintained KBANN or NofM code was found.

**PROPEL** (Verma et al., NeurIPS 2019) is the closest modern design. It keeps a policy h = π + λf, where π is a program and f a neural residual. It alternates a policy-gradient step on the residual ("lift") with synthesis of a new program that imitates the mixed policy ("project"), and it ships the *program* ([arXiv 1907.05431](https://arxiv.org/pdf/1907.05431); code at bitbucket.org/averma8053/propel per the paper). On the TORCS racing simulator, the neural DDPG baseline is faster where it works. It crashed in more than half the seeds on two tracks (crash ratios 0.68 and 0.92), while the PROPEL programs completed every track. The programs also transferred to unseen tracks with far fewer crashes, and a smoothness property was verified in Z3 in 0.49 s. PROPEL initialized from a neural policy often failed, but initialized from a simple hand-written program it often succeeded ([arXiv PDF](https://arxiv.org/pdf/1907.05431)). The user's cycle replaces "project by imitation" with "fix the program on failing cases", and PROPEL's residual is the natural shape for a later "fine-tune the rest of the net around the frozen fix" step. VIPER (NeurIPS 2018) extracts verifiable decision trees from a DNN policy. When verification found a counterexample, the fix went into the environment (a longer paddle), not the model ([arXiv 1805.08328](https://arxiv.org/abs/1805.08328v2)). **Deep distilling** turns specially trained "essence" networks into code that generalizes to problems orders of magnitude larger than training ([arXiv 2111.08275](https://arxiv.org/abs/2111.08275v1); [pauljblazek/deepdistilling](https://github.com/pauljblazek/deepdistilling)).

**GAM Changer** (Wang et al., KDD 2022) is the human-in-the-loop version on glass-box models. Data scientists edit the shape functions of a generalized additive model directly, with live global, region and subgroup metrics, monotonicity projection by isotonic regression, and a git-style edit history ([ar5iv 2206.15465](https://ar5iv.arxiv.org/abs/2206.15465); [interpretml/gam-changer](https://arxiv.org/pdf/2112.03245)). Its authors state that the safeguards "do not guarantee to prevent users from overfitting". One showcased edit rested on 19 patients, and an edit to age shifted outcomes for women disproportionately ([ar5iv](https://ar5iv.arxiv.org/abs/2206.15465)). Lengerich et al. then showed that **GPT-4 can read GAM shape graphs, flag anomalies that contradict domain knowledge, and suggest repairs** ([arXiv 2308.01157](https://arxiv.org/abs/2308.01157v1)). The follow-up warns that such answers are "helpful suggestions rather than final answers" ([arXiv 2402.14474](https://arxiv.org/pdf/2402.14474)). LLM-GS (ICLR 2025) has an LLM write programs that hill-climbing then repairs against reward. It is the nearest case of an LLM proposing a program and search validating it ([arXiv 2405.16450](https://arxiv.org/abs/2405.16450v2)). Older explanation-feedback methods (Right for the Right Reasons, CAIPI) turn human corrections into training constraints rather than edits ([arXiv 1703.03717](https://arxiv.org/abs/1703.03717); [arXiv 1805.08578](https://arxiv.org/pdf/1805.08578)).

The novelty claim should name that last row and nothing broader. The searches cannot exclude unpublished hobby work. Two unverified 2025–26 leads, "Gradient-based program repair" and "Neuron-Anchored Rule Extraction", were found but not read ([arXiv 2505.17703](https://arxiv.org/abs/2505.17703); [arXiv 2605.03058](https://arxiv.org/pdf/2605.03058)). The distinctive artifact the repo can show is something no weight-space method produces: **a readable diff of a network repair**, the faithful program next to the fixed one, which a reviewer can audit line by line.

## Step 4 should test the fix on planted bugs before Iris

The first design decision follows from the KBANN comparison. The repo's snapping already "fixes" nets without seeing failing data. Any cycle experiment has to separate that snapping gain from the gain of fixing with failing cases, or it will credit the agent with what `nice()` already does. The second follows from Zhou's distinction between rule extraction *using* nets and extraction *for* nets ([arXiv 2312.12878](https://arxiv.org/pdf/2312.12878)). The current checker loop is extraction *for* the net, judged by fidelity. The fix cycle is extraction *using* the net, judged by task accuracy, so fidelity becomes a side-effect to report, not a target. The third follows from scope. In the repo's 1–4-input nets the block *is* the whole network, so "reinsert" collapses into "deploy the program". Reinsertion only means something with layers around the block, which step 4 needs to build on purpose.

**Populations.** Four sets, in order of how much they can tell. *P1, planted-bug formula nets*, should come first. Retrain the existing formula tasks (absolute difference, median, tax brackets, window, xor) with one controlled defect each: label noise in one bracket, a hole in the training range, or a shifted breakpoint. The net is then wrong in a known region with a known correct fix, and the true formula supplies unlimited fresh failing and passing inputs. This mirrors how PRDNN used fog-corrupted MNIST and ACAS Xu polytopes ([ar5iv 2104.04413](https://ar5iv.labs.arxiv.org/html/2104.04413)). *P2* is the existing formula nets whose faithful program still misses the true formula. Checked against `runs/*/results.json`, that is only 3 of the 29: tax seed0 and seed1 (the net learned blurred, misplaced brackets) and xor seed2 (the net never learned xor). Snapping already fixes every other trained net, and the hand-built nets are correct. Failing cases are disagreements with the true formula beyond tolerance. *P3* is the 12 Iris nets, with failing cases being misclassified flowers under repeated cross-validation. These failures are few, and many sit in the versicolor/virginica overlap, where no clean rule exists. Reading P3 as more than a stress test for overfitting would be unwise. The repo's own 96.7% versus 95.3% is a gap of about two flowers. *P4* is a two-block composite net, such as an absolute-difference block feeding a threshold block, trained end to end with a planted defect in one block. Fix block A only, block B only, and both, then compare. This is the cheapest test of Hase et al.'s warning before step 6 meets it in a transformer.

**Arms.** Each fix should start from the same faithful program, already checked against the net, and use the same split: a *repair set* of failing inputs the fixer sees, and a *held-out failure set* it never sees, frozen before any run. The fixer arms are four. The blind Claude agent gets the program, the repair set with labels, and a sample of passing inputs. An I/O-only Claude gets the same data without the program, the cycle's analogue of the existing B5 baseline. A deterministic constant refit keeps the program's structure and refits only thresholds and coefficients to the labelled data, then snaps; this is the RAPTURE-style "constants only" control. A human is optional. The weight-space baselines are: fine-tuning on the repair set plus the original training data; the early-stopped conservative fine-tune; PRDNN/APRNN on the same repair set (APRNN needs a Gurobi license); Arachne if its code installs; and retraining from scratch on more data as a reference ceiling. For the code arms, reinsertion has four variants. R-code runs the fixed program on CPU in place of the block. R-exact compiles the program with the CPWL identities and an ε-ramp for any jump, and reports the probability mass inside the ε margin. R-LP uses the fixed program's outputs on repair points and anchor points as the target of a PRDNN-style single-layer repair. R-distill fine-tunes the block on dense samples of the fixed program, then re-decompiles it to check whether the fix survived, given Tracr's mechanism-drift result.

**Metrics.** Report PRDNN's triple for every arm: efficacy on the repair set, generalization on the held-out failures, and drawdown on originally-correct inputs. Add Arachne-style unseen-failure generalization as the headline, because a fix that only covers shown inputs is a lookup table ([KAIST record](https://dspace.kaist.ac.kr/handle/10203/307190)). Add true-task accuracy on fresh data from the formula, inside and outside the training range. Report fidelity to the original net separately on the training support and off it. The Iris nets extrapolate arbitrarily, so off-support disagreement is reported but not penalized. Following GAM Changer, report locality as the fraction of outputs changed and the input volume of the changed region, and report the support count: the number of training points inside the changed region, flagging any fix justified by fewer than about ten ([ar5iv](https://ar5iv.arxiv.org/abs/2206.15465)). Add program size before and after, and a special-case detector for branches or constants that equal a repair input. For P4, report end-to-end accuracy after reinsertion. Where a property is known (monotonicity, bracket rates, symmetry of |a−b|), check it exhaustively on a grid, as PROPEL did with Z3. Report agent tokens and wall time, and medians over seeds with failure counts, as PROPEL did over 25 seeds ([arXiv 1907.05431](https://arxiv.org/pdf/1907.05431)).

**Risks.** Memorization is the main risk. The fixer sees the failing inputs and can write `if x == ...` branches, which the held-out failure set, the special-case detector and the size guard exist to catch. Label leakage is new: the current agent is task-blind, but a fixer given labels can infer the task, so the I/O-only arm and the constant-refit arm are needed to show that reading the program, not guessing the task, did the work. On Iris, "failures" may be label noise or class overlap, and fixing them lowers true accuracy. On compile-back, jumps make R-exact approximate, and steep ramps make later fine-tuning unstable ([arXiv 2311.12786](https://arxiv.org/pdf/2311.12786)). On localization, a failure traced to block A may be fixed better in block B ([arXiv 2301.04213](https://arxiv.org/pdf/2301.04213)), and different seeds can learn different algorithms for the same task ([Clock and Pizza](https://proceedings.neurips.cc/paper_files/paper/2023/hash/56cbfbf49937a0873d451343ddc8c57d-Abstract.html)), so one block's fix may not transfer across seeds. Finally, fine-tuning can win on generalization, as PRDNN's MNIST case showed. The study has to be able to report that result.

## Conclusion

The literature splits the problem along an axis the user's idea crosses. Weight-space repair is precise and sometimes provable, but nobody can read its edits. Glass-box editing is readable, but it has never been applied to a decompiled block of a trained network and put back. The repo's snapping result suggests the bridge could be worth more than either side: a fix expressed as a short program diff is a strong regularizer, and the 16-of-29 snapping wins came with no failing data at all. The decisive experiment is therefore not "can an agent fix a decompiled block" but "does it fix *held-out* failures better than fine-tuning and PRDNN, at lower drawdown, with a diff a person can audit". Planted-bug formula nets can answer that cleanly. Iris cannot.

The cycle also has an implication for steps 5 and 6. Because the repo's programs are verified equal to the block before any fix, the code-on-CPU option has none of the fidelity gap that sinks approximate replacements such as cross-layer transcoders. For CPWL fixes, the weights option is exact by construction. The open technical question is narrower than it first looks: what to do with genuine jumps, where a ReLU block can only approximate the fixed program and a CPU branch reproduces it exactly. That question is where "compile back to weights" and "keep as code" stop being interchangeable, and step 4's R-exact margin measurements should map it before step 6 meets it inside a transformer.
